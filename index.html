def python_fundamentals(candidate):

Python

~6 min

  • Core data structures — Lists, dicts, tuples, sets; can explain when to use which and why.

    AskWhen would you use a tuple instead of a list? Why can't a list be used as a dictionary key?

  • Variables & mutability — Scope, mutable vs immutable types, common gotchas.

    AskIf I pass a list into a function and append to it inside, does the original list outside change? Why?

  • OOP basics — Classes, objects, `__init__`, basic inheritance.

    AskWrite a small class with an `__init__` and one method. What's the difference between an instance attribute and a class attribute?

  • Decorators mastery not expected — Recognizes what a decorator is and roughly how it's used.

    AskWhat does `@staticmethod` do? Have you used or seen a decorator like `@property` before?

  • Writes actual code — Ask them to write a short function live. Evaluate the code they produce, not just what they describe.

    AskGiven a list of order dicts like `{"customer": "A", "amount": 120}`, write a function that returns total spend per customer.

  • Data exposure — What formats/datasets they've handled: CSV, JSON, APIs, dataframes, etc.

    AskWhat's the difference between reading a CSV with plain Python vs pandas? When would you reach for each?

def sql_deep_dive(candidate): weighted focus area

SQL

~9 min

  • Query writing — SELECT, JOIN types (inner/left), GROUP BY, HAVING, filtering logic.

    AskGiven `customers` and `orders` tables, write a query that returns all customers and their orders — even customers who never ordered anything.

  • Window functions — RANK/ROW_NUMBER, LAG/LEAD, PARTITION BY; do they know when to reach for one over a GROUP BY.

    AskUsing a sales table with region, month, and sales columns, how would you find each region's previous month's sales? (LAG + PARTITION BY)

  • Aggregate reasoning — Can explain why a query breaks or returns wrong grouping, not just write syntax from memory.

    AskWhen would you use SUM vs COUNT vs AVG, and how does each behave with NULLs? What's the difference between WHERE and HAVING?

  • Concept fluency — CTE vs subquery, UNION vs UNION ALL, and when each is the right call.

    AskWhat's the difference between a CTE and a subquery? Between UNION and UNION ALL — when would performance push you toward one?

  • Writes an actual script highest weight — Give a small sample schema and have them write a real query live. Score primarily on what they write.

    AskGiven a `customers` table, write a query to find any `customer_id` that appears more than once.

  • Optimization awareness stretch, optional — Basic sense of why a query might be slow (indexes, full scans).

    AskYour query is running slow on a large table — walk me through how you'd investigate and speed it up.

def data_eng_and_devops(candidate):

Data Eng & DevOps

~6 min

  • ETL/ELT concept — Can explain extract → transform → load in their own words, with an example.

    AskWalk me through, in your own words, what happens to data between a source system and a warehouse.

  • DB concepts — Normalization, primary/foreign keys, relational vs non‑relational, fact/dimension modeling at a basic level.

    AskWhat's the difference between a fact table and a dimension table? Between a star schema and a snowflake schema?

  • Git basics — Clone/commit/push/pull, what a branch is, merge vs rebase awareness.

    AskWalk me through the commands you'd use to start a new feature: create a branch, commit a change, and get it ready for review.

  • Code hygiene — Readable naming, comments, no hard‑coded values where they shouldn't be.

    Ask[Show a short snippet] What would you rename or restructure here to make it easier for a teammate to read?

  • Secrets awareness — Do they know a leaked key needs rotating, not just deleting the line.

    AskYou just noticed you pushed an API key to a public repo five minutes ago. What do you do right now?

  • Docker/containers awareness level — Knows roughly what a container is and why teams use one; not expected to build images.

    AskIn plain terms, what's a container, and why would a team use one instead of just running code on a VM?

def data_interpretation(candidate):

Data Interpretation

~4 min

  • Come with a real data sample — A small table or chart (e.g. weekly signups by channel, ticket resolution times by team, sales by region) — hand it to the candidate and let them work from it directly, rather than an abstract scenario. Paste or describe the exact sample you'll use in the box below so it's consistent across interviewers.

    Sample datasetWeekly signups for 4 marketing channels over 6 weeks, where one channel (e.g. "Referral") has quietly doubled while the others are flat.

  • Reads the data correctly first — States what's actually in front of them (axes, units, time period) before interpreting it.

    AskBefore we go further, what is this table actually showing — what's each column, and over what period?

  • Spots patterns / anomalies — Trends, outliers, or breaks in the numbers, not just a row-by-row description.

    AskWhat stands out to you in this table? Is anything moving differently than the rest?

  • Gets to "so what" — Moves from observation to insight: what this likely means and why it might be happening.

    AskWhy do you think Referral signups jumped like that? What are two or three plausible explanations?

  • Turns insight into action — Proposes a next step, decision, or thing they'd check next, not just a description of the data.

    AskIf this were real, what would you do next — what would you look into, or recommend to the team?

  • Flags uncertainty appropriately — Asks about data source/definitions or names what they'd verify before acting on it, rather than overreaching from a small sample.

    AskHow confident are you in that explanation with only 6 weeks of data? What would you want to check before acting on it?

Communication & Fit

~3 min

  • Clarity — Explains a technical idea so a non‑technical listener would follow.

    AskExplain what a JOIN is to someone with no technical background.

  • Adaptability — Responds well when pushed back on or redirected mid‑answer.

    TryPush back on an earlier answer — "I don't think that's quite right, walk me through your reasoning again" — and see how they respond.

  • Motivation — Why Launchpad, why this track, what they're hoping to learn.

    AskWhat made you apply for this track specifically, and what do you want to be able to do by the end of it?

  • Team fit — Collaboration signals, energy, how they'd describe their working style.

    AskTell me about a time you had to ask for help on something you didn't know how to do — what happened?
